## 概述

读取一个或多个节点导出JSON文件（字段包含 `name` / `type` / `server` / `port`），输出经过去重后的汇总表格。

- 每行代表**一个归一化后的主机**，该主机全部端口合并至同一个单元格。
- 保留文件提取时间以及来源机场标记。
- 同步归档原始 mihomo / clash YAML 配置文件。

> 
> 核心逻辑由脚本实现：`scripts/build_node_list.py` — **禁止手动复写聚合逻辑**。

> 
> [!NOTE]
> 本能力仅做静态文件分析。不会启动客户端、读取进程内存、测试节点连通性，也不会做DNS解析。

## 输出约定

输出CSV固定列顺序如下：

| 节点IP或域名 | 端口 | 提取时间 | 来源机场 |
| --- | --- | --- | --- |
| 1.ltdflix‑space.xyz | 58001,58002,58081 | 2026‑11‑18 11:52:53 | KooDog |
| cdn.rockzf.lol | 12933,13230,53679 | 2026‑11‑18 11:52:53 | RocketVPN |

规范说明：

1. 端口使用英文逗号分隔，**不要加空格**，保证单元格为单一字段。
2. **一个主机仅占一行**，不要把原始每条节点记录拆分成多行。
3. 时间戳取自导出文件修改时间；同一个机场所有行使用相同时间。
4. 机场标签从导出文件元数据解析，**不是读取文件夹名称**。

## 工作流程

### 1. 定位导出文件

匹配文件模式：`*nodes.json`、`*_nodes.json`、`*Nodes.json`。

典型目录示例：

- 客户端完整导出：`output/<机场名>_nodes.json`
- 中间采集文件：`apex_nodes.json`、`wy_nodes.json`、`zy_core_nodes.json`
- 带平台后缀目录：`wandacloud‑windows/_re/output/nodes.json`

执行规则：

- 如果用户指定文件夹，则在该目录内扫描。
- **禁止重新拉取订阅、重新采集、启动客户端、读取进程内存**，只处理磁盘上已存在的导出文件。
- 如果缺少必需的导出文件，列出缺失文件并终止流程。

### 2. 运行构建脚本

#### 自动扫描模式（推荐）

```
python scripts/build_node_list.py --root <扫描根目录> --out <输出目录>
```

> 
> ⚠️ 重要：`--out` 输出目录**必须放在扫描根目录外面**，否则下次运行会把自己生成的结果当做输入重新扫描。脚本也会自动排除输出目录。

#### 清单文件模式（用于精确标记来源、附加额外YAML）

```
python scripts/build_node_list.py --manifest manifest.json --out <输出目录>
```

`manifest.json` 示例：

```
{
  "sources": [
    {
      "label": "KooDog",
      "nodes": "output/KooDog_nodes.json",
      "yaml": "output/KooDog_config.yaml"
    }
  ],
  "extra_yaml": [
    {"label": "misc", "path": "extracted/FlClashMisc.yaml"}
  ],
  "raw_dirs": ["extracted"]
}
```

可用参数：

| 参数 | 说明 |
| --- | --- |
| `--strict-info` | 彻底丢弃订阅公告行对应的端口 |
| `--no‑archive` | 不复制归档原始YAML配置 |

### 3. 内置去重归一化规则

所有归一化逻辑已经内置在脚本中，不要自己手写去重代码。

**来源标签解析**

- 文件 `X_nodes.json` → 来源标签 `X`。
- 剔除平台后缀：`_windows` / `-win64` / `-macos`。
- 剔除无效采集前缀：`apex`、`core`、`app`、`wy`、`zy`。
- 降级策略：取最近有效父目录名，最终兜底值为 `unknown`。

**子集过滤**

- 如果一份导出文件的（主机+端口）集合完全包含于另一份导出，判定为中间采集产物，跳过并打印日志。
- 两份导出端点集合完全相同时，保留可读性更好的来源名称。

**占位主机过滤**

> 
> 这些是订阅公告占位地址，不是真实代理节点：
> `1.1.1.1`、`0.0.0.0`、`127.0.0.1`、`localhost`、`::1`、`::`
> 包含以上地址的条目直接丢弃。

**订阅公告行处理**
节点名称包含以下关键词视为公告行：

> 
> 中文：`剩余流量`、`套餐到期`、`距离下次重置`、`请更新订阅`、`官网`、`到期`
> 英文：`remaining`、`expire`、`traffic left`、`reset in`

- 默认行为：公告行的主机端口依旧合并进表格，但该行不计为有效节点。
- 使用 `--strict‑info`：公告行对应的端口一并丢弃。

**端口解析清洗**

- 统一端口格式：`"443"`、`"080"`、`443`、`443.0` → `443` / `80`。
- 无效端口直接丢弃：0、大于65535、非数字；丢弃原因标记为 `invalid‑host‑or‑port`。

**主机归一化**

- 域名全部转为小写。
- 移除IPv6地址外层方括号 `[]`。
- 剔除URL协议头和末尾路径。> 
> `Example.COM` 和 `example.com` 会合并为同一行。

### 4. 结果校验

脚本写完CSV之前会做自检：

- 表头严格匹配预期
- 表格行数等于去重后唯一主机数量
- 每行4列全部不为空
- 所有端口数字范围 1‑65535

控制台输出校验样例：

```
校验: N 行 / M 个端口 / 唯一 host K
```

> 
> 务必引用脚本打印的这行校验信息，不要自己主观判定结果是否正确。

> 
> [!WARNING]
> 校验通过**不等于节点可以连通**，本流程不做DNS解析和TCP连通测试。

### 5. 输出报告

自动生成 `REPORT.md`，内容包含：

- 每个机场统计：原始条数 / 有效节点 / 公告条目
- 按端口数量排序的高频主机排行
- 所有被丢弃条目的明细与拒绝原因

对话侧需要向用户总结：

1. 唯一主机总数量
2. 汇总端口总条数
3. 有多少行是合并了多个端口
4. 哪些机场的导出文件解析失败

## 产物说明

输出目录结构：

```
<out-dir>/
├── node_list.csv          # 主数据表，4列
├── node_list.json         # 结构化数据：端口数组、提取时间、丢弃记录
├── REPORT.md              # 统计信息 + 丢弃原因审计日志
└── yaml/
    ├── <机场名>.yaml      # 每个来源可直接加载的 mihomo/clash 配置
    └── raw/               # 原始导出文件，包含加密 *.dat 文件
```

归档规则：

- 即便用户只想要表格，也要归档YAML配置。
- 二进制加密文件（`*.dat`）原样复制到 `yaml/raw/`，标记为未解密。**禁止尝试解密**。

## 常见问题与故障排查

| 现象 | 根因 | 处理方案 |
| --- | --- | --- |
| 来源机场出现重复，例如同时出现 `apex` 和 `龙猫云` | 采集前缀被误识别为机场名称 | 脚本由 `WEAK_STEMS` 和子集过滤处理；查看脚本打印的跳过日志 |
| 某个机场完全不出现在结果表 | 导出文件名后缀不是 `nodes.json` | 修改文件名，或者写入 manifest.json |
| 去重后部分端口消失 | 公告行端口被过滤 | 默认保留公告端口；`--strict‑info` 参数才会移除 |
| 输出行数异常偏多 | 输出目录放在扫描根目录内，把生成文件当做输入 | 将 `--out` 移到外部，或清理旧产物再运行 |
| Excel打开CSV中文乱码 | 缺少UTF‑8 BOM标记 | 脚本默认使用 `utf‑8‑sig` 编码输出 |
| 来源机场列显示`解析失败` | JSON文件损坏/截断 | 直接上报解析失败，**不要编造虚构节点数据** |

## 能力边界

✅ 支持范围：

- 处理用户已经提供、存放在本地磁盘上的配置导出文件。

❌ 不做这些操作：

- 拉取远程订阅链接
- 向服务端做身份认证
- 解密加密配置文件
- 读取正在运行的客户端进程内存
- 主动网络探测、连通性测试

> 
> [!IMPORTANT]
> 如果节点数据只存在客户端运行时内存，没有静态导出文件，需要明确告知用户静态文件不足，并说明需要运行时提取才能拿到数据。**不要悄悄切换到运行时提取逻辑。**
